# Broker telemetry fixture

This test fixture retains the reviewed TF1 reporter, relocated OTLP v1.9.0 bindings and host-listener correction. The reporter implements MetricsReporter and ClientTelemetryExporterProvider; it receives exporter push-interval context. It is not a client runtime dependency.

Select one file, `docker-compose.telemetry.yml`, with project `kafkajs`. Bootstrap on `localhost:19092`, `localhost:19095` and `localhost:19098`; Metadata must return those same host endpoints. The published bindings use IPv4 loopback. The test socket uses IPv4 explicitly for these fixture hostnames, records the actual remote address and port, and refuses every other endpoint before dialing. This test choice does not change the library socket default. TLS/SASL host listeners are not published by this fixture and are not part of this plaintext fixture proof.

Every broker mounts the matching reporter jar, with `metric.reporters=org.countly.kafkajs.telemetry.CountingTelemetryReporter` and `telemetry.max.bytes=4096`. `fixtures/manifest.json` records exact source, jar, proto, compiler, image and corrected compose identities. No jar is committed. Before the cluster starts, `fetch.sh` downloads only the inputs pinned by `fixtures/inputs.sha256` into `TF1_CACHE` and verifies each hash, and `build.sh <line>` builds the reporter jar deterministically from the committed source into `fixtures/`. `run.sh verify <line>` then requires that jar to match the manifest digest, so any changed byte fails readiness. Broker start never builds, downloads or pulls. The independent decoder uses protobuf-java 3.25.5, the pinned Kafka client jar and relocated bindings in the reporter jar. Set `TELEMETRY_JAVA_CACHE` to the same directory as `TF1_CACHE`: it holds the `jars/` directory. Missing or changed inputs fail readiness.

`run.sh verify 4.3.1` checks the retained manifest, compose, source, build script and selected reporter jar. `run.sh decode 4.3.1 /absolute/raw.bin` also verifies the Java cache and independently decodes one decompressed payload of at most 4096 bytes. Both commands are offline and require a private `TMPDIR`. The runtime observer decompresses captured Push bytes using Node built-ins with an output cap, then matches their SHA-256, UUID and node to the broker sink and successful Push response. A capped sink record alone cannot prove all metric values: full decoding is mandatory when detail is truncated. Zero-byte Push has no exporter record and must be proved from the wire.

Each run gets a fresh `TELEMETRY_EVIDENCE_DIR`. The reporter queue holds at most 128 entries and each broker file at most 2 MiB; a record holds at most 4096 bytes of JSON detail. Any OVERFLOW marker, sequence gap, decode failure, stub, unmatched accepted Push or observer limit breach fails the fixture. Readers retain a cursor for each broker independently. Archive completed evidence before clearing the sink after the brokers stop; never clear or rotate an active sink.

The maintained runtime subscription is `metrics=org.apache.kafka.`, `interval.ms=1000`, with an anchored match for the run's four client IDs. Create, list, describe, delete and read back through the completed public CLIENT_METRICS APIs. Every auxiliary admin has telemetry disabled. The preparation-only narrow Java subscription and two-file negative capture are historical evidence, not runtime invocation forms.

CI selects the same file for startup, readiness, evidence verification and teardown through `scripts/testWithKafka.sh`: the `telemetry-reporter` lane runs the `reporter export` and `reporter no-resource control` cases on `docker-compose.telemetry.yml`, and the `telemetry-base` lane runs `reporter no-plugin control` on the unchanged `docker-compose.yml`. The package's nine `test:e2e:telemetry-*` scripts call the controller's reviewed live guard directly and select one exact Jest file and test title; the controller supplies P9_CLUSTER_GUARD and KAFKA_VERSION. No script starts Compose independently. Natural client and child exit and empty owned project resources are required after cleanup. Base no-plugin controls use one selected base file and record actual advertisements; a missing subscription on a configured exporter is a different case.
