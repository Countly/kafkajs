The test cluster is a 3-broker Kafka cluster running in [KRaft mode](https://kafka.apache.org/documentation/#kraft) (no ZooKeeper) — each of the three nodes is a combined broker+controller. It's defined in [`docker-compose.yml`](../docker-compose.yml) at the root of the repository, and started with `docker compose` (requires `docker` and the `docker compose` plugin — see [Development Environment](DevelopmentEnvironment.md)).

## Starting the cluster

```sh
./scripts/dockerComposeUp.sh
```

This runs `docker compose -f docker-compose.yml up`, using the compose file's default broker image `apache/kafka:4.4.0`. Override the version with the `KAFKA_VERSION` environment variable:

```sh
KAFKA_VERSION=4.1.2 ./scripts/dockerComposeUp.sh
```

Set `NO_LOGS=1` to return immediately instead of following the container logs.

## Cluster layout

Each node exposes three listeners: plaintext, SSL, and SASL_SSL (PLAIN/SCRAM). The internal (broker-to-broker and controller) traffic uses `kafka1:29092`, `kafka2:29095` and `kafka3:29098`, which isn't exposed to the host.

| Node   | PLAINTEXT | SSL  | SASL_SSL |
|--------|-----------|------|----------|
| kafka1 | 9092      | 9093 | 9094     |
| kafka2 | 9095      | 9096 | 9097     |
| kafka3 | 9098      | 9099 | 9100     |

All three listeners are reachable at `localhost:<port>`. SSL and SASL_SSL clients need the test CA certificate at `testHelpers/certs/cert-signed` (regenerated by [`scripts/generateKafkaCertificates.sh`](../scripts/generateKafkaCertificates.sh)). SASL PLAIN users (`test`, `bob`, `alice`) are defined in [`testHelpers/kafka/server-jaas.conf`](../testHelpers/kafka/server-jaas.conf); the SCRAM user (`testscram` by default) is created separately with [`scripts/createScramCredentials.sh`](../scripts/createScramCredentials.sh).

This is a test-only cluster: authorization is wide open (`super.users=User:ANONYMOUS`, `allow.everyone.if.no.acl.found=true`) so it should never be exposed beyond local development.

## Running commands against the cluster

Kafka's CLI tools are available inside each container. For example, to list topics:

```sh
docker exec kafka1 /opt/kafka/bin/kafka-topics.sh --bootstrap-server kafka1:29092 --list
```

A few helper scripts wrap common admin operations against `kafka1`:

- `TOPIC=my-topic PARTITIONS=3 ./scripts/createTopic.sh`
- `TOPIC=my-topic PARTITIONS=6 ./scripts/addPartitions.sh`
- `CLIENT_ID=my-client PRODUCER_BYTES=1024 CONSUMER_BYTES=1024 ./scripts/setClientQuota.sh`

## OAuth (OAUTHBEARER) variant

An alternate compose file, [`docker-compose.oauthbearer.yml`](../docker-compose.oauthbearer.yml), configures the same 3-node layout with the `OAUTHBEARER` SASL mechanism instead of PLAIN/SCRAM. Select it with `COMPOSE_FILE`:

```sh
COMPOSE_FILE=docker-compose.oauthbearer.yml ./scripts/dockerComposeUp.sh
```

## Stopping the cluster

```sh
docker compose -f docker-compose.yml down --remove-orphans
```

(use `-f docker-compose.oauthbearer.yml` if that's the variant you started).

See the [Producer example](ProducerExample.md) for how to connect to and use a running broker, and [Testing](Testing.md) for how the cluster is used by the test suite.
