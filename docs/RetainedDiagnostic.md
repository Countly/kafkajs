# Retained-memory ownership diagnostic

Use this diagnostic when the telemetry resource arms fail their retained-memory checks. It records where retained memory grows (engine code and metadata, module caches, harness state, client state) so that growth can be attributed to an owner. It is diagnostic only: its records are marked `diagnostic: true, acceptanceEligible: false`, the resource acceptance gate rejects them, and it changes no acceptance limit, schedule or baseline.

The separate `retained-diagnostic` CI job selects Node 24 and runs the six broker-free control groups before invoking:

```sh
node scripts/e2e/telemetry/retainedDiagnostic.js --diagnostic-only "$RETAINED_DIAGNOSTIC_DIR"
```

This selector requires CI, a quiet resource lane and a fresh output directory. It refuses the acceptance artifact directory. It starts exactly sixteen serial children: public and collector arms, producer/consumer/admin/shareConsumer kinds, and capture/scalar variants for each identity. It keeps the 90-second inclusive watchdog, 120-second outer case bound, ten-second terminal receipt-to-close bound, 30-minute execution step and 45-minute job. An exhausted budget or capacity produces incomplete evidence; there is no retry, shortened schedule or larger acceptance budget.

Each child performs five disabled lifecycles with three operations each, preserves C0 after the first and C1 after the fifth, and releases the disabled fixture before constructing the enabled population. It preserves the original M, executes the cold block 0 and five further blocks on the same returned client or collector/builder, then joins cleanup and releases the remaining workload roots. Public blocks keep 128 legal descriptors and the assigned UUID and each execute five opens/fifteen operations, including gzip and zstd current/retired/reopen work and public payload decoding. Collector blocks restore 64 nodes/257 points and fresh transport authority on the same builder; a retired null builder cannot supply completion proof. Intermediate closes are labelled separately from the terminal receipt.

Capture children write exactly seven raw heap snapshots in order: C0, C1, disabled-released, M, closed-0, closed-5, all-released. Scalar children execute the same checkpoints without writing snapshots. Each capture records its own SHA-256, byte length, actual monotonic observation/capture times and pre/post scalar readings. Snapshot bytes stream through the hash reader rather than being retained as an evidence buffer in the target heap.

Diagnostic capacities are fixed in `retained/contract.js` before CI: 2,048 events, 32 MiB total event bytes, 512 native jobs/windows, 90 foreground operations, 131,072 weak targets, 16 KiB per raw process-status record and 512 MiB per snapshot. The event transport reserves its buffer before C0. Every completed scalar event is written immediately to the child sidecar. Overflow fails completion; the normal 32-window acceptance sampler and 64-KiB stdout allowance stay unchanged.

The artifact contains source copies and digests, parent-issued identities, per-child `events.jsonl`, stdout/stderr and `record.json`, every GC pair, all six original-M closed deltas, raw peak-source text/parse/time/process identity, operation/native completions and weak observations. `diagnostic-summary.json` reports diagnostic completion separately from numerical screens and never publishes acceptance `ok`. Decreasing authoritative peaks remain failures; missing capability or inconsistent coverage remains inconclusive. Snapshot perturbation and scalar counterparts are never subtracted from old measurements.

The offline `retained/analyse.js` command emits `ownership.json` and per-capture ownership detail. It compares consecutive snapshots, C0 and original M using stable IDs and additive self bytes, including additions/removals, resizing and category transfers. It enumerates backing-store identities and aliases, material named retaining properties and uncapped consequential code/feedback/prototype references. Labelled WeakMap dependencies use a separate AND(table,key) fixed-point liveness analysis and dependency-removal controls; ordinary dominators alone cannot prove ephemeron release. Runtime/code labels classify their own storage and do not exempt instance descendants. Residual/unclassified bytes remain explicitly quantified.

Graph generation is not a reviewed owner verdict. The reports deliberately leave `attributionComplete:false`: review the material cold increments, old/new stores and aliases, expected block-0/block-5/all-released lifetimes, intentional factory/close state and unknown remainder before proposing any later method amendment. A later plateau corroborates boundedness but does not explain first-use ownership. CI must preserve partial and failed evidence and always upload `retained-diagnostic-node24`. The normal resource gate, live matrix, acceptance schema 6, limits and schedules remain independent.
